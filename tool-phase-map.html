Why you've only seen jina in practice

  1. Phase 3 fallback magnet. jina read <url> is the final fallback for LinkedIn, YouTube, and "any other site". apify costs $0.05+ per call so operators skip; brightdata binary is missing on this host — so jina catches everything that was supposed to fall through.
  2. Silent-drop bugs hid the others. Pre-R24 (commit 4a42795), merge-volley.sh rejected envelopes whose shape didn't match {schema_version, provider, command, result}:
    • jina emits bare {"results":[…]} → silently dropped until R24 added an envelope wrap.
    • tvly emits raw Tavily API body → silently dropped until R26 (today's commit) added a wrap.
    • perplexity / exa: own CLIs, envelope-correct. May have lacked env vars in earlier runs.
    So the visible survivor each week was whichever provider's shape happened to match. Post-R24 + R26, all four providers should land in 01-seed.json.
  3. L2 escalation tier = jina. Phase 6 cost-ladder L2 is literally jina read + tvly extract; tvly extract only became real at R26.
  4. Cost ladder pressure. L1 cheap, L2 jina cheap (~free with key), L3 apify ~$0.05/call, L4 perplexity-deep multi-dollar. Operators' natural floor lands on jina.

Not "others bad/broken" — others were silently dropped (envelope mismatch), expensive (apify / L4), or uninstalled (brightdata).
